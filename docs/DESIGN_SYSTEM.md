# Design System — MeCodex (v9, content fill + new home sections)

> Single source of truth for the live system in `website/css/style.css`. Reuse rather than reinvent.
> v3 was a visual-weight pass on top of v2's system (same tokens, same anti-pattern list). v4 was a first motion pass; the client escalated with "animation in every corner" feedback, so v5 is a full motion sweep — every section on every page now carries deliberate motion (ambient, entrance, hover, or scroll-triggered), while staying one coherent choreographed system rather than random effects. v6 adds two specific client-requested effects on top of v5: an ambient particle-dot background sitewide, and a system-wide "numbers tumble" language (odometer-style digit flip for the hero stat counters, flip/rotate entrances for every decorative index numeral). v7 is a further client escalation ("continue, add more animation/detail") layering pointer-driven interaction (tilt, magnetic buttons), scroll parallax, section-divider line-draws, icon stroke-draws, a form-success burst, and a scroll-to-top affordance on top of v3–v6 — while consolidating the listener/rAF footprint rather than growing it 1:1 with each new effect. No new sections, claims, colors, or content were added in v3–v7. v8 expanded the site from 4 to 8 pages (FAQ, Work/Portfolio, Careers, Insights) plus two new sections on existing pages (Home FAQ, About tech-stack elevation) — built entirely on the tokens/components/motion language below, adding exactly one new reusable component (Accordion) rather than a parallel visual system. **v9 fills the three v8 "coming soon" pages with real (illustrative/generic, honestly-framed) content and adds two new homepage sections** (Featured Work, From the Blog) — no new components, only new content and two small additive CSS pieces (a tag-chip variant and article/job-listing typography) layered onto the existing Accordion/`.engagement-card`/`.section-head` language.

## Colors
- Teal `#33E0C7`, Blue `#3D6CF2` — accents only (eyebrow dots, gradient text, icon strokes, hover states, focus rings). Never used as full-section fills.
- Ink Dark `#0A0F1C` — primary background (`--surface-0`).
- Ink Light `#EAF6FF` — primary text on dark (`--text-primary`).
- Neutrals (derived from Ink Dark/Light, for restraint — no pure black/white):
  - `--surface-1: #0E1424`, `--surface-2: #131b30`, `--surface-3: #182140`, `--surface-4: #202b4d` — layered dark surfaces (cards, panels, form fields).
  - `--border-subtle: rgba(234,246,255,.09)`, `--border-strong: rgba(234,246,255,.18)`, `--border-accent: rgba(51,224,199,.4)`.
  - Text: `--text-secondary` (.66 alpha), `--text-muted` (.44 alpha), `--text-faint` (.22 alpha, decorative index numerals only).
- `--gradient-brand` (teal→blue, 135deg) used sparingly: eyebrow dot, hero headline highlight word, primary button fill, active nav underline, process step-index hover.

## Typography
- Display/headings: IBM Plex Mono (500/600/700).
- Body: Inter (400/500/600/700).
- v3: `h1`/`h2` set to weight 700 with slightly tighter tracking (`-0.015em`) for a heavier, more authoritative register; `h3`/`h4` stay 600 so hierarchy doesn't flatten. Eyebrows tightened from `letter-spacing: 0.16em` to `0.19em` with explicit `font-weight: 600`.
- Fluid clamp-based scale (`--text-*` custom properties):
  - `--text-display: clamp(2.75rem, 1.6rem + 3.6vw, 5rem)` — hero H1 only.
  - `--text-h1: clamp(2.25rem, 1.6rem + 2.2vw, 3.25rem)` — page H1s (about/services/contact).
  - `--text-h2: clamp(1.7rem, 1.35rem + 1.3vw, 2.5rem)`.
  - `--text-h3: clamp(1.1rem, 1.02rem + 0.3vw, 1.3rem)`.
  - `--text-body-lg: clamp(1.05rem, 1rem + 0.2vw, 1.2rem)` — `.lead` paragraphs.
  - `--text-body: 1rem`, `--text-caption: 0.85rem`, `--text-label: 0.76rem` (eyebrows/uppercase labels), `--text-button: 0.88rem`.
- Line-height: 1.12 for headings, 1.6 body.
- Measure: body paragraphs capped at `max-width: 62ch`; `.lead` at `54ch`.

## Layout
- Container: `--container-width: 1240px`, fluid inline padding `clamp(1.25rem, 4vw, 2.5rem)`.
- Spacing scale (`--space-*`): 3xs .25rem, 2xs .5rem, xs .75rem, sm 1rem, md 1.5rem, lg 2.5rem, xl 4rem, 2xl 6rem, 3xl 8.5rem. Section vertical rhythm uses `--space-2xl` (desktop) / `--space-xl` (≤640px).
- Radius: `--radius-sm: 8px` (icon chips, inputs), `--radius-md: 14px` (unused directly, reserved), `--radius-lg: 20px` (reserved for large panels), `--radius-pill: 999px` (buttons, stack chips). Editorial list rows, service details, CTA panel, and value rows are intentionally **square** (borders/dividers, not rounded cards) — this is the anti-"rounded-everything" decision.
- Shadows: restrained, interaction-only. `--shadow-soft` / `--shadow-lift` appear only on hover states (buttons, engagement cards); nothing has a resting glow/shadow.
- Header height: `--header-height: 80px` (shrinks 12px + gains background/border once scrolled, see Motion).

## Motion principles
- Base timings: 220ms base / 480ms slow, custom ease `cubic-bezier(.16,.8,.32,1)`. v4 stagger delays are additional `transition-delay`/`animation-delay` values layered on top of these, not new easing curves.
- Hover: translateY lifts on buttons/cards, underline draws on links, tint sweep on editorial rows, icon-chip/index color shifts. v4 adds: icon micro-rotation/scale on service-row and nav-menu-item icons (`scale(1.12) rotate(-4deg)`), `.engagement-card` gains a hover-only tinted glow shadow (still no resting shadow — same restrained-shadow policy as v3), `.btn-primary` shifts its gradient's `background-position` on hover for a subtle "alive" gradient feel (no rainbow cycling, no autoplay).
- Scroll: header scroll-state class **plus a scroll-progress accent bar** (`.scroll-progress`, 2px gradient fill at the header's top edge, width driven by `main.js` from `scrollY`). IntersectionObserver-based `.reveal` fade/rise-in, native smooth-scroll for in-page anchors.
- **Staggered list reveals (v4)**: `.service-row`, `.why-item`, `.value-row` are no longer animated as a single block — each row/item fades+rises individually via CSS `transition-delay` (0/90/180/270ms) once its parent list (`.service-rows`/`.why-list`/`.values-list`) gets `.is-visible` from the existing IntersectionObserver — no new JS, pure CSS nth-child delays. `.process-step` markers pop in (scale 0.4→1) and their connecting line segments draw in (`scaleX(0→1)`) with the same staggered nth-child delays, keyed off each step's own `.reveal.is-visible` state. `.grid > .reveal` sibling pairs/triples (story-grid, contact-grid, why-grid, engagement-grid) get a small nth-child stagger too.
- **Hero entrance (v4)**: on page load (not scroll-gated), the hero's eyebrow/H1/lead/CTAs/visual/index-rail fade+rise in a short staggered sequence (`heroEnter` keyframe, 0–360ms delays, ~700ms each) instead of appearing instantly.
- **Hero stat counters (v4)**: `.hero-statbar` numbers count up via a small `requestAnimationFrame` counter in `main.js` when scrolled into view. Only strictly-numeric stats (optionally with a trailing `%`) are counted; non-numeric formats (`24/7`, `3 yrs+`) are left as plain fade/rise — never mis-counted.
- **Nav mega-menu (v4)**: open/close transition slowed to `--transition-slow` with a fade+rise (was an instant-feeling fast fade); its 4 items stagger in via nth-child `transition-delay` (30–150ms), pure CSS, no JS.
- Hero network SVG: one slow (40s) rotating dashed orbit ring + a very small (8px, 9s ease-in-out) drift on the network group, existing node pulse, plus **(v4) two small "data packet" dots travelling along the connection lines** via CSS motion-path (`offset-path`/`offset-distance`, ~4.6s/5.4s loops, fade in/out at path ends) — reinforces the network/data motif, degrades harmlessly to a static dot where `offset-path` isn't supported.
- All motion — including every v4 addition above — respects `prefers-reduced-motion: reduce`: staggered/hover/entrance/counter/packet animations are disabled and content shows in its final state instantly; the stat counter script itself checks the media query and skips the RAF loop entirely rather than just hiding the result visually.
- No parallax-on-mousemove, no autoplay video, no scroll-jacking, no infinite marquees. "More animation" means more of the same purposeful language applied more often — not new visual gimmicks.

### v5 — full motion sweep (client: "animation in every corner")
- **Section-head reveal, generalized**: every `.eyebrow → h1/h2 → lead` block site-wide (`.section-head`, plus the homepage's `.why-intro` variant) now reveals its own children in sequence (eyebrow → heading → lead → callout, ~100ms apart) instead of fading as one flat block. This is what makes every page's first screen "arrive" — about/services/contact's top `.section-head` uses the exact same mechanism as the homepage hero's entrance, just scroll-gated instead of load-gated (it's already in view on load, so it fires immediately).
- **Headline word-reveal**: hero H1 and each page's H1 wrap their words in `.word` spans (`main.js`, DOM-node-safe — preserves the hero's nested `.text-gradient` span as one word unit) that cascade in via `--i`-driven `transition-delay` on top of the block-level rise above. Scoped to H1s only (short, headline-length text) per the "no full-paragraph word-splitting" guidance; H2s keep the block/child-stagger treatment instead.
- **Ambient sitewide motion (always-on, pre-scroll)**: `body::before`'s soft radial glow now drifts slowly (`bgDrift`, 34s, transform/scale only, oversized 10% past the viewport so no seam is visible) so no page is fully static even before interaction. Every `.eyebrow::before` dot pulses gently (`eyebrowPulse`, 2.6s). Services-page ghost numerals breathe (`ghostBreathe`, 6s, opacity+scale). All three are transform/opacity-only, one element each (or per-eyebrow, bounded by section count) — not a performance concern.
- **Cursor-aware spotlight**: `.service-row`, `.value-row`, `.why-item`, `.contact-info-item` get a soft radial highlight that follows the pointer on hover, driven by `--mx`/`--my` custom properties set from a single rAF-throttled `mousemove` listener per element (`main.js` §8). Scoped behind `@media (pointer: fine)` in CSS and gated behind a `matchMedia("(pointer: fine)")` check in JS, so touch devices get neither the listener nor the CSS — nothing is half-styled.
- **Footer reveal-in**: `.footer-top` (brand + 3 nav columns) now cascades in on scroll via the same `.reveal`/`IntersectionObserver` pattern as everything else, instead of sitting static.
- **Contact form polish**: submit now shows a brief `.is-loading` spinner state on the button (`btnSpin`, ~650ms simulated send, skipped instantly under reduced motion) before the success message appears; the success message itself scales/fades in (`.form-success.is-shown`) and its checkmark polyline draws on with `stroke-dashoffset` (`checkDraw`) instead of just popping into view. Form fields get a `:focus-within` label color tint and a 1px focus lift.
- **Micro-interaction sweep**: logo gets a subtle hover scale, footer/social icons rotate+scale on hover, tech-stack chips (about.html) stagger in on scroll (4-item tiers) and gained a hover background tint (previously border/color/lift only), service-detail icons (services.html) get the same hover rotate/scale already used on service-row/nav-menu icons, contact-info icon chips get a hover scale, `.engagement-card` hover shadow is now transitioned (was an instant snap). Closed every remaining "bare instant `:hover`" gap found in a full sweep (e.g. `.contact-info-item a` had a color hover with no transition — fixed).
- All v5 additions are covered by a dedicated block in the `prefers-reduced-motion: reduce` query (disables every new `@keyframes`/`animation`/stagger-transition added in this pass; hover-triggered transitions that remain are short and user-initiated, consistent with prior passes).

### v6 — particle background + number flip (two specific client requests)
- **Ambient particle field** (`.bg-particles`, `website/js/main.js` §9): a single fixed, full-viewport `<canvas>` behind all content on every page (`position: fixed; inset: 0; z-index: -1; pointer-events: none;`, `aria-hidden="true"`), drawn/animated by a small vanilla-JS particle system — no library. 16–42 low-opacity teal/blue dots (count scales down below 640px/1024px viewport width) drift slowly in randomized directions and wrap at the canvas edges; deliberately sparser and lower-opacity than the hero's own foreground network diagram so it reads as ambient texture, not a second competing diagram. Pauses its `requestAnimationFrame` loop when the tab is hidden (`visibilitychange`) and redraws (not just resizes) on viewport resize (debounced). Under `prefers-reduced-motion: reduce`, the loop never starts — one static frame is painted and left in place.
- **Number-flip system** — the client's "بتلف بتتشقلب" (spinning/tumbling, odometer-style) request, applied consistently everywhere the site already used numerals as editorial/data texture:
  - **Hero stat counters** (`.hero-statbar .stat-num`): the existing v4 count-up now renders as an odometer/split-flap digit roll instead of a smooth linear increment. `main.js` §6 splits the counted value into per-digit `<span class="digit">`s (zero-padded to the target's digit count) and steps through a handful of discrete intermediate values (not every rAF frame) — each digit that changes retriggers a `digitFlip` `rotateX` keyframe (340ms) via a classList remove/reflow/add cycle, so it snaps like a flap counter rather than blurring. Non-numeric stats (`24/7`) are unaffected — still plain fade/rise, per the existing v4 rule.
  - **Ghost numerals** (`.service-detail-ghost`, services.html): now flip/rotate in (`ghostTumbleIn`, 620ms, `rotateX` + scale) the first time their `.service-detail` scrolls into view (piggybacking on the existing sitewide `.reveal` observer), then hand off into the v5 `ghostBreathe` ambient loop.
  - **Row-index numerals** (`.step-index`, `.row-index`, `.feature-num`, `.value-mark`) — process steps, service rows, why-items, and about-page value rows all now flip/rotate in (`scale(0.5) rotateX(65deg)` → identity) timed with each row's existing stagger delay (0/90/180/270ms), instead of a plain opacity fade or (for `.step-index`) a flat scale-pop.
  - All flip/rotate containers gained a `perspective` value on their parent (`.hero-statbar .stat-num`, `.service-row`, `.why-item`, `.value-row`, `.process-step`, `.service-detail`) so the `rotateX` reads as a real 3D flip rather than a flat squish.
- `prefers-reduced-motion: reduce` covers both v6 additions: the particle canvas never starts its loop (static dots only), and every flip/tumble collapses to an instant/fade appearance — no `rotateX`, no digit-roll count-up (the stat counter script skips digit-span construction entirely under reduced motion, same pattern as the v4 count-up skip).
- No new libraries. Files touched: `website/css/style.css`, `website/js/main.js`, all 4 HTML files (added `<canvas class="bg-particles" aria-hidden="true">` after the skip link).

### v7 — interaction/parallax pass (client: "continue, add more animation/detail")
- **Tilt** (`.tilt`, `main.js` §8): subtle 3D tilt on hover, `perspective() rotateX() rotateY()` driven by `--tilt-x`/`--tilt-y` custom properties. `.service-row` / `.why-item` / `.value-row` get a small range (max ~4°, since rows are full-width); `.engagement-card` gets a slightly larger range (max ~7°, narrower cards). `.engagement-card:hover`'s existing lift transform is merged with the tilt rather than the two fighting over the `transform` property. `pointer: fine`-gated in both JS and CSS; requires motion to be allowed (tilt listeners are simply never attached under `prefers-reduced-motion: reduce`).
- **Magnetic buttons** (`.magnetic`): `.btn-primary`/`.btn-secondary` translate a few px toward the cursor within their own hover zone (`--mag-x`/`--mag-y`), merged into the existing hover-lift transform, snapping back on `mouseleave` via the transform transition already on the button.
- **Scroll parallax**: gentle `translateY` (capped 16px) on `.hero-visual-frame` and (capped 10px) on `.bg-particles`, computed inside the same rAF-throttled scroll handler that drives the header state and progress bar (`main.js` §0) — not a second scroll listener. Targets `.hero-visual-frame`, not `.hero-visual`, because the latter still owns the v4 `heroEnter` load-in `animation` on `transform`; writing an inline transform to the same element/property the animation targets would just be overridden by it.
- **Section divider line-draw** (`.section-divider` / `.divider-line`): a thin 1px brand-gradient rule between major sections (index/about/services, 3 per page) that draws itself (`scaleX(0→1)`) via the existing `.reveal`/IntersectionObserver system — no new observer, the divider just carries the `.reveal` class like everything else.
- **Icon stroke-draw**: the two most-seen icon contexts — homepage `.service-row` and services-page `.service-detail` card icons — now "draw" in (`stroke-dasharray`/`stroke-dashoffset`) keyed off the same `.service-rows.is-visible`/`.service-detail.is-visible` state their rows already use, instead of just appearing. CSS-only, no HTML/JS changes.
- **Form-submit success burst**: a single soft teal ring (`successPulse` keyframe, ~900ms) pulses outward from the success checkmark once `.form-success.is-shown` is set — reuses the exact class `main.js` already toggles for the v5 checkmark-draw, no new JS. Brand teal only, no confetti.
- **Nav underline gradient sweep**: `.primary-nav a::after`'s underline now shifts `background-position` on hover (same technique as `.btn-primary`'s existing hover) instead of sitting as a flat two-color gradient fill. Logo idle-pulse was considered and skipped as unnecessary risk to the logo SVG markup.
- **Scroll-to-top** (`.scroll-top`): fixed bottom-right button, fades in past ~60% of viewport height scrolled (toggled by the same consolidated scroll handler), smooth-scrolls to top on click (`behavior: "auto"` under reduced motion).
- **Listener/loop consolidation**: `main.js` now computes `reducedMotion` once at the top of the file (removed 3 duplicate `matchMedia` re-declarations). The scroll listener count did not grow — still exactly one `scroll` listener (rAF-throttled), now also driving parallax and the scroll-to-top toggle. Pointer effects (spotlight/tilt/magnetic) share a single Map-based rAF batch (`flushPointerFX`) rather than one rAF token per effect; there is still one `mousemove` listener per interactive element (matching the v5 spotlight pattern), just funnelled through one shared flush. rAF *loops* (continuous, not one-shot) remain exactly one: the particle canvas.
- `prefers-reduced-motion: reduce` covers every v7 addition: tilt/magnetic listeners are never attached in JS (primary guard) plus a defensive CSS `transform: none !important` override; scroll parallax never writes a transform; divider lines and icon strokes render fully drawn; the success burst ring is disabled (the checkmark's own v5 fade/draw rules already handle the reduced-motion case).
- No new libraries. Files touched: `website/css/style.css`, `website/js/main.js`, all 4 HTML files (scroll-to-top button; section dividers on index/about/services; `.success-icon-wrap` span in contact.html).

## Depth & texture system (v3)
Purpose: make the site read as "engineered" rather than flat cards on a dark background, without adding new content or leaning on glassmorphism/glow.
- **Two-tier background grid** (`body::after`): fine 64px hairline grid layered with a second, slightly-more-visible 128px grid, both masked to fade out by ~78% of viewport height. Site-wide, always-on, restrained (line opacity 0.05 / 0.08 via `--grid-line` / `--grid-line-strong`).
- **`.grid-plane` utility**: a reusable "blueprint plane" (fine grid, radial-masked so it fades at the edges) for any section/element that wants extra depth beyond the global grid — not currently required anywhere the global grid doesn't already cover, kept as a documented utility for future sections.
- **Hero visual layering** (`.hero-visual::before`, `.hero-visual-frame`): a soft teal radial vignette + a tighter 32px grid sit behind the network SVG, radially masked; the frame gets small corner brackets (reusing the corner-bracket motif at a slightly larger scale) and a very low-opacity horizontal scanline sweep (`@keyframes scanline`, 7s, disabled under `prefers-reduced-motion`). A small mono "readout" line (`.hero-visual-readout`) sits under the existing `// system.map` caption with literal, non-fabricated counts of the diagram's own nodes/links (`nodes: 09`, `links: 12`, `state: stable`) — decorative HUD detail describing the SVG itself, not a product claim.
- **Corner-bracket reuse**: the existing `.bracket-frame` motif (previously CTA panel only) is now also applied to `.engagement-card` (services page) and `.contact-form`, so the "engineering blueprint" accent reads as a deliberate system rather than a one-off.
- **Footer weight**: a 2px gradient hairline accent on the footer's top border (`.site-footer::before`) plus a small mono wordmark/status line, `.footer-meta` ("// MeCodex — Engineering Studio"), added next to the copyright line — visual polish only, no new claims or links.

## Explicit anti-patterns (per client brief — avoided)
Glassmorphism-everywhere, meaningless gradients, huge rounded corners everywhere, floating pills everywhere, excessive shadows/glow, generic "AI landing page" look, identical grid repeated for every section (services/why/process/CTA each use a distinct layout: editorial rows / asymmetric list+callout / offset timeline / two-column bracket panel).
